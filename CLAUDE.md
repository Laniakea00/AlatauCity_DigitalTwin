# AlatauCity_DigitalTwin: правила для Claude

Этот файл читает любой Claude Code, открытый в этой папке. Над проектом работают два Claude на двух компьютерах, через этот git. Полный контекст: `docs/HANDOFF.md`, прочитай его перед первой задачей.

## Проект в двух строках

Демо-цифровой двойник нового города Alatau City (платформа qTwin) для государства и инвесторов. Unity 6000.0.84f1, Built-in Render Pipeline, сборки Windows и WebGL (сайт https://laniakea00.github.io/AlatauCity_DigitalTwin/).

## Правила владельца (Anuar), обязательны

1. **Код только по явной просьбе.** Вопрос («почему так?», «это баг?») означает только объяснение: ответить, указать `файл:строку`, описать исправление словами и остановиться. Попутно ничего не чинить, соседние баги называть, но не трогать. Просят изменить: менять только то, что просили.
2. **Необратимое только с вопросом:** удаление файлов насовсем, `push --force`, `reset --hard`, переписывание истории, деплой, публикация, релиз, отправка во внешние сервисы.
3. **Коммиты:** сообщение одной короткой строкой, без тела. НИКАКИХ `Co-Authored-By`, «Generated with», `Claude-Session` и другой атрибуции, ни в коммитах, ни в PR. Коммит и пуш только когда Anuar скажет «коммить» / «пуш». Релиз на GitHub делает сам Anuar.
4. **Каждый ответ начинать с `**TL;DR:**`** (1–2 предложения). Если есть проблема (баг, риск, упавший шаг, решение за Anuar), TL;DR говорит о ней.
5. **Отвечать по-русски, коротко и понятно.** Тема считается незнакомой: каждый термин пояснять одной фразой.
6. **Не просить Anuar нажимать клавиши, обновлять страницы, запускать скрипты.** Всё, что можно сделать самому, делать самому. Неизбежные просьбы собирать в одну.
7. **Несрочные проблемы** не писать в ответы, а дописывать в `docs/problems_later.md` (дата · где · что · предложение).

## Правила данных

- **Сейчас 2026 год.** Шкала двойника 2026–2050, «2025» нигде не писать.
- **Реальных данных нет и не будет до контракта.** Берём открытые данные (пресса, генплан, OSM, спутник). Где их нет, синтетика «как настоящая» с пометкой «модель qTwin» (чипы источников: `Data/Sources.cs`, `UI/SourceTags.cs`). Не предлагать «подключить реальные данные» как улучшение.

## Технические запреты

- Никогда не коммитить: `RefPhotoDownloader.cs` (+.meta), `ShotRig.cs` (+.meta), папку `Assets/Editor/AlatauRemote/`, удаления `PerformanceTestRun`.
- Ключи API (Gemini и любые) никогда не в репозиторий, не в сборку WebGL, не в чат.
- Сохранять окончания строк CRLF там, где они есть.
- Не менять сжатие WebGL. Заставка «Made with Unity» выключена во всех сборках, не включать.
- `Resources/Loc/strings.json` записан одной строкой: при конфликте слияния объединять ключи обеих сторон, никогда не брать одну сторону целиком.

## Работа вдвоём через git

- Сейчас вся работа идёт от ветки `Map` (в `main` на GitHub только этапы 1–3, его обновит Anuar). Свою задачу делать в своей ветке от `Map`, перед началом `git pull`, по ходу регулярно вливать `Map` в свою ветку.
- В `main` и `Map` вливает и пушит только Anuar или Claude по его слову «пуш».
- Не трогать чужие файлы (кто чем владеет, в `docs/HANDOFF.md`, раздел «Кто что делает»). Нужна правка в чужом файле: сказать Anuar, он передаст.
- Сцену `.unity` и `ProjectSettings/` одновременно не править: только один Claude и только по договорённости.

## Инструменты

- Gemini (тестер, проверка кадров и дизайна, генератор картинок, переводы): `tools/claude/README.md`. Ключ только в переменной окружения `GEMINI_API_KEY`, его даст Anuar.
- Генератор карты: `tools/map/` (описание в `docs/HANDOFF.md`, раздел 5).
