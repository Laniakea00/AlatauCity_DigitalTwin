# ИИ-прокси цифрового двойника Alatau City

Небольшой сервер-посредник между двойником (WebGL-сайт и Windows-сборка) и Gemini API.
Ключ Gemini хранится **только на этом сервере** (переменная окружения `GEMINI_API_KEY`); в сборке и в репозитории ключа нет.

## Как это работает

1. Во вкладке «ИИ» зритель задаёт вопрос. Unity (`Assets/Scripts/DigitalTwin/Ai/AiClient.cs`) отправляет на прокси `POST /chat`:
   `{ "lang": "ru|en|kz", "contents": [...], "tools": ["fly_to", ...], "model": "" }`.
2. Прокси сам добавляет системную инструкцию и описания функций (они живут в `core.js`, клиент их не задаёт — поэтому прокси нельзя использовать как «открытый» доступ к Gemini), вызывает `generateContent` и возвращает
   `{ "model", "text", "calls": [{ "name", "args", "id" }], "content": "<ход модели в JSON>", "finish" }`.
3. Если модель попросила функции, двойник выполняет их **на своих данных** (`Ai/AiTools.cs`): `fly_to`, `open_module`, `show_layer`, `get_city_stats`, `get_project`, `get_monitoring`, `get_sources`, `analyze` — и отправляет результаты следующим запросом. Ход модели (`content`) возвращается без изменений.
   - `analyze(topic, year?, phase?)` — готовые расчёты двойника, те же, что у сценарных ответов (`AiModule.Analysis`): `school_deficit`, `school_site`, `construction_risk`, `power_shortage`, `flood`, `lrt_delay`, `traffic`, `population`. Возвращает числа и названия, готовую сводку и описание того, что показано на карте; карточка ответа получает ту же подсветку, камеру, легенду и график, что и сценарный ответ.
   - `open_module` не переключает вкладку сам (иначе ответ пропал бы вместе с вкладкой «ИИ»): под ответом появляется кнопка «Открыть вкладку «…» →».
   - Модель пишет простой текст без Markdown (так требует системная инструкция); клиент на всякий случай убирает разметку (`Ai/AiText.cs`): `**x**` → жирный, `* `/`- ` → `• `, без `#`.
4. Модель отвечает текстом на языке интерфейса. Под ответом двойник показывает источники (чипы из `Data/Sources.cs`) и список вызовов; камера летит к объекту.
5. Если прокси не настроен, недоступен или не ответил за 15 с, показывается прежний сценарный ответ с пометкой «офлайн‑режим: ответ по сценарию».

Правило честности (в системной инструкции): любые числа — только из результатов функций; если данных нет — «нет данных в двойнике»; числа модели QTwin называются моделью, а не официальными данными.

## Файлы

| файл | что это |
|---|---|
| `core.js` | общая логика: системная инструкция, функции, проверка запроса, вызов Gemini, CORS, ограничение частоты |
| `server.js` | сервер для Node 22 (без npm-зависимостей) |
| `worker.js` | тот же контракт для Cloudflare Workers (не развёрнут) |
| `test/twin_stub.js` | функции двойника для теста, построены на реальных данных репозитория (повторяют `AiTools.cs`) |
| `test/twin_analyze.js` | `analyze` для теста: перенос расчётов `AiModule` на те же файлы данных (buildings.csv и traffic.json берутся из `TWIN_BUILDINGS_CSV` / `TWIN_TRAFFIC_JSON`) |
| `test/run_test.js` | тестовый клиент: имитирует цикл Unity и пишет протокол в Markdown |

## Запуск локально

```bash
cd UnityProject/Tools/ai_proxy
GEMINI_API_KEY=<ключ> node server.js          # порт 8787
curl http://localhost:8787/health              # {"ok":true, ... "key":"set"}
node test/run_test.js http://localhost:8787 transcripts.md
SET=w9 node test/run_test.js http://localhost:8787 transcripts_w9.md   # шесть подсказок вкладки «ИИ» + EN/KZ
```

Затем в `UnityProject/Assets/StreamingAssets/ai_config.json` указать адрес:

```json
{ "proxyUrl": "http://localhost:8787", "model": "" }
```

Пустой `proxyUrl` (по умолчанию) — ассистент работает как раньше, по сценарию. `model` пустой = `gemini-3.5-flash`.

## Переменные окружения

| переменная | по умолчанию | смысл |
|---|---|---|
| `GEMINI_API_KEY` | — | ключ Gemini (обязательно) |
| `PORT` | `8787` | порт |
| `AI_EXTRA_ORIGINS` | — | дополнительные разрешённые Origin через запятую (например, свой домен) |
| `RATE_PER_MIN`, `RATE_BURST` | `30`, `12` | запросов в минуту с одного IP и запас «рывка» (один вопрос = 2–3 запроса) |
| `TRUST_PROXY` | — | `1`, если сервер стоит за обратным прокси: IP берётся из `X-Forwarded-For` |

## Защита

- Ключ — только из окружения; в логах только метод, путь, код ответа и время. Тела запросов и ответов не пишутся.
- Модели — только из списка `gemini-3.5-flash` (по умолчанию, быстрая), `gemini-3.8-flash`, `gemini-4-argon`.
- Запрос не больше 64 КБ, не больше 24 ходов, текст вопроса до 2000 символов; разрешены только текст и функции двойника (картинки, файлы, роль `system` и чужие функции отклоняются).
- CORS: `https://laniakea00.github.io`, `http://localhost:*`, `http://127.0.0.1:*`, `null` (сборка, открытая из файла). Windows-сборка заголовка Origin не шлёт и проходит без CORS. Чужие сайты получают 403.
- Ограничение частоты по IP; ответ модели ждём не дольше 25 с.

## Где разместить (решает владелец)

Сайт двойника — статический (GitHub Pages), поэтому прокси нужен отдельно. Варианты:

1. **Cloudflare Workers** (бесплатный тариф обычно достаточен): `wrangler deploy worker.js`, ключ — `wrangler secret put GEMINI_API_KEY`. Лимит частоты внутри воркера приблизительный; для жёсткого лимита добавить правило Rate Limiting в Cloudflare на `/chat`.
2. **Любой VPS / Render / Fly.io / Railway** с Node 22: `node server.js` за HTTPS (Caddy или nginx), `TRUST_PROXY=1`.

Совместимость: клиент присылает список своих функций, прокси отдаёт модели только их пересечение со своими. Новый клиент работает со старым воркером (без `analyze`, ответы на вопросы о школах и стройке тогда беднее), старый клиент — с новым. После изменения `core.js` пересобрать `cloudflare/worker.js` (`python3 build_worker.py`) и заново развернуть воркер.

После размещения прописать HTTPS-адрес в `ai_config.json` и пересобрать сайт. Сайт на `https://` может обращаться только к прокси на `https://`.

Что стоит учесть: каждый ответ — платный вызов Gemini по ключу владельца. Ограничение частоты защищает от случайной нагрузки, но не от целенаправленного злоупотребления; при публичном размещении стоит выставить лимит расходов (квоту) на ключ в Google AI Studio / Cloud Console.
