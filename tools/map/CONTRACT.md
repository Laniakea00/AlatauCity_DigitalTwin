# Map pipeline contract (Stage 7, levels 1–2)

This file is the interface between the workers of levels 1 and 2. Code to it exactly. If something here is wrong or missing, do the sensible thing in your own files, keep the field names below, and list the change in your final report; the orchestrator updates this file. Units: Unity metres, X = east, Z = north, Y = absolute height above sea level (the datum of `terrain_heights.bytes`). JSON is UTF-8, LF, compact (no indent) for files over 1 MB.

## 1. Pipeline and ownership

```
spec/city.json + spec/<district>.json (v1)          ← cartographer (own district only); city.json ← orchestrator only
   │ gen/gen_network.py   → OUT/<d>/network.json     ← w43
   │ gen/gen_lrt.py       → OUT/<d>/lrt.json         ← w43
   │ gen/gen_blocks_lots.py → OUT/<d>/blocks.json, lots.json      ← w44
   │ gen/gen_buildings.py → OUT/<d>/buildings.json   ← w44
   │ gen/gen_masks.py     → OUT/<d>/features.json    ← w44 (parking, stops, greens, plazas, no-plant)
   │ validate/validate_map.py → OUT/<d>/report.json, report.md, report.png   ← w43 core; rule files by owner (§5)
   │ export/merge_districts.py → OUT/_merged/<run>/Assets/...  (the files Unity reads) + gen_twin re-run   ← w45
   ▼
Unity (laptop, orchestrator only): roads/traffic/lamps/people readers ← w45; trees/LRT/parking/districts/solar/norms readers + Iconic move ← w46
```

- `tools/map/run.py <district>` (w43) runs the whole chain for one district in order and stops at the first failing step. Every generator is also runnable alone: `python3 tools/map/gen/<tool>.py <district> [--out OUT]`.

- Existing level-0 code in `tools/map/geo`, `tools/map/registry`, `tools/map/scheme` stays; reuse it (`geo/terrain.py` for height and slope, `geo/frames.py` for transforms, `geo/render_maps.py` for drawing).
- Current twin data (read-only input, LFS files included): `TWIN = /mnt/user-data/uploads/AlatauCity_DigitalTwin/UnityProject/Assets` (`StreamingAssets/twin/*.json`, `CityData/{buildings.csv,layer_buildings.bytes,layer_infrastructure.bytes,terrain_heights.bytes,city_meta.json}`, `Resources/Landmarks/*`). Formats: `/mnt/project-files/alatau_stage7/research/code_map.md` §1–2. The integ clone has no LFS files; never write into `TWIN`.
- Open data from level 0: `/mnt/project-files/alatau_stage7/level0/w34/` (`osm/roads.geojson`, `osm/buildings.geojson`, `osm/connectors.geojson`, `osm/rail.geojson`, `osm/water.geojson`, `osm/infrastructure.geojson`, `derived/*.geojson`; README.md explains each). ## 2. Vocabulary (from `spec/norms.json`, never invent new keys)

- Road classes = keys of `norms.road_classes` / `norms.street_profiles`: expressway, arterial_road_regulated, arterial_continuous, arterial_regulated, district_transport, district_pedestrian, local, local_secondary, industrial, park_road, driveway_main, driveway_secondary, village_main, village_secondary, village_lane, pedestrian_street, boulevard, bike_path, ramp.
- Node types = keys of `norms.node_types`: crossing, crossing_signal, right_in_right_out, roundabout, square, diamond, partial_cloverleaf, cloverleaf, trumpet, directional, grade_separation. Allowed pairs: `norms.node_matrix` (by `norms.road_classes[c].node_group`). Extra node kinds that are not junction types: `end` (allowed dead end with turnaround), `joint` (city.json joint or trial-area edge), `edge` (city boundary), `merge`, `diverge` (ramp ends on an expressway), `ic` (internal node of an interchange).
- Structure kinds along a segment: ground, embankment, cut, bridge, overpass, tunnel. Level of a span: bridge/overpass = +1, tunnel = −1, others 0.
- Zone uses: as in level 0 (`mixed_centre, business, residential_high, residential_mid, residential_low, village_existing, campus, medical, industry, logistics, utility, park, waterfront, sport, reserve`).
- Lot uses: the zone uses plus social and service kinds: school, kindergarten, polyclinic, hospital, clinic, pharmacy_shop, college, university, fire_station, police, sport_ground, park, square, playground, parking, utility, substation, transit (LRT / bus / rail station), worship, culture, landmark (a keep object).
- Years: always 4 values `[base, fast, slow, infra]` (the twin's scenarios, `UnityProject/Tools/twin_gen/twin_common.py`). Existing things (2026 already standing) = `[2025, 2025, 2025, 2025]`. 2099 = not by 2050 (avoid: every planned thing gets a real year).

## 3. District spec v1 (`spec/<district>.json`, version 1)

Keeps every level-0 key (district, boundary, targets, centres, axes, zones, lrt, objects, phases, joints, checks) and adds:

- `area` (optional): `[[x,z],…]` work polygon. Generators and the validator only build and check inside `area ∩ boundary`; merge replaces the current twin only inside `area`. `gate_trial` must have it.
- `edge_joints`: for an `area` smaller than the district: `[{id, x, z, class, connects: "twin_edge:<roads.json edge index>" | "osm:<overture id>"}]`, where the trial network meets the current map at the area edge.
- `streets`: `[{id, class, line:[[x,z],…], name_ru, years:[4], oneway:false, profile:{…optional overrides of norms.street_profiles[class]}, struct:[{from:[x,z], to:[x,z], kind}], source:"keep_existing:<overture id>"|"new", axis:"<level-0 axis id>"|null}]`. Only the skeleton and the streets the cartographer wants by hand; gen_network adds the local grid inside blocks by the zone rules, village streets between existing houses (`village_*`, label «модель qTwin»), and every interchange ramp from its node template.
- `nodes`: `[{id, x, z, type, streets:[ids], params:{…template options, e.g. "quadrants":["ne","sw"], "loop_r":60, "major":"<street id>"}, ramps?:{"<ramp id or movement>": {lanes, from_year?, why_ru?}}}]` — every junction the cartographer decides. At-grade crossings not listed get a default node by `node_matrix`; a crossing the cartographer wants grade-separated without ramps is a node of type `grade_separation`.
- `keep`: `[{id, what_ru, polygon, registry_id|null, attach:[{street_id, x, z}]}]` — land that the generators must not touch (Gate District quarter with Iconic, QAIST, etc.). Their own streets come from the twin data as they are; new streets connect at `attach` points.
- `views`: `[{id, registry_id, apex:[x,z], dir_deg, fov_deg, len_m}]` — view sectors of landmark façades (rule 17).
- `zones[i].rules`: `{floors:[min,max], height_cap_m, far, block_side_m:[min,max], setback_m, lot_split:"perimeter"|"towers"|"rows"|"houses"|"campus"|"industrial"|"none", parking:{per_home, per_100m2_office, per_100m2_retail, type:"underground"|"multi"|"surface"}, homes_per_ha, jobs_per_ha}`.
- `lrt` v1: `{lines:[{id, line:[[x,z],…], sections:[{from:[x,z], to:[x,z], kind:"ground"|"elevated"|"tunnel"}], stations:[{id, name_ru, x, z}], ends:[{kind:"depot"|"terminus", id}], years:[4]}], depots:[{id, polygon, years}]}`.
- `objects[i]` (v0 rows) may add `lot_m2` / `footprint` (`[[x,z],…]`) / `kind` (lot use) so gen_blocks_lots can give a registry object its lot.

## 4. Generator outputs (`OUT/<d>/`)

`network.json` (w43):
```
{schema:"qtwin.network/1", district, area,
 profiles:{"<pid>":{class, lanes:[fwd,back], lane_w, median_w, sidewalk_w:[l,r], verge_w:[l,r], bike_w:[l,r], parking_w:[l,r], red_line_w}},
 nodes:[{id, x, z, y, kind, ic|null, r|null, lrt?}],
 segments:[{id, a, b, class, pid, oneway, pts:[[x,z,y],…], struct:[{from_m, to_m, kind}], years:[4], name_ru, street|null, ic|null, source?, stages?:[{years:[4], pid, lanes, why_ru}]}],
 interchanges:[{id, template, x, z, major, minor, ramps:[segment ids], structures:[segment ids], ramp_lanes?:[{key, lanes, from_year:[4]|null, segments:[ids]}]}],
 joints:[{id, node}], log:[{what, ids}]}
```
`y` in `pts` is the road surface height; `oneway` segments are one carriageway (a divided road is two oneway segments). Nothing is dropped silently: anything removed is in `log`.

`lrt.json` (w43): `{schema:"qtwin.lrt/1", lines:[{id, pts:[[x,z,y_rail],…], sections:[{from_m,to_m,kind}], stations:[{id,name_ru,x,z,chain_m,platform_m,kind}], ends:[{kind,id}], years:[4]}], depots:[{id,polygon,years}]}`.

`blocks.json` / `lots.json` (w44): `{schema:"qtwin.blocks/1", blocks:[{id, zone, use, polygon, area_m2}]}`, `{schema:"qtwin.lots/1", lots:[{id, block, use, polygon, grade_y, years:[4], registry_id|null, source:"registry"|"rule"|"existing"|"keep", capacity:{places|beds|homes|jobs|cars: n}}]}`.

`buildings.json` (w44):
```
{schema:"qtwin.buildings/1",
 buildings:[{id, bid|null, lot|null, footprint:[[x,z],…], floors, height_m, base_y, use, kind, model, source:"existing_osm"|"existing_twin"|"registry"|"model", registry_id|null, years:[4], build_years, gfa_m2, homes, jobs, keep_mesh:bool}],
 removed:[twin bids removed inside area], solar:[{polygon, years}]}
```
`bid` is set only for kept twin buildings (`keep_mesh` true: their mesh stays as it is in layer_buildings.bytes). New buildings get `bid:null`; merge assigns the final number (§6). `kind` and `use` must map onto `buildings.csv` columns.

`features.json` (w44): `{schema:"qtwin.features/1", parking:[{id,type:"surface"|"multi"|"underground",cap,levels,polygon,lot,years}], stops:[{id,kind:"bus"|"lrt"|"rail",x,z,segment}], greens:[{id,kind:"park"|"square"|"boulevard"|"yard"|"buffer"|"sport",polygon,years}], plazas:[{id,polygon}], noplant:[{polygon,why}]}`.

All outputs carry `years` per object so rule 23 can compare a building with the street that serves it.

## 6. Unity files written by merge (w45) and who reads what

`merge_districts.py [--districts gate_trial,…] [--base TWIN] --run <name>` writes a full set of changed Unity files to `OUT/_merged/<name>/Assets/…` (same relative paths as in the project) plus `OUT/_merged/<name>/manifest.json` (file → md5, size, what changed). Mode «district + current data»: outside the districts' `area` everything stays as in `TWIN`.

- Roads (w45 writes and reads in C#): `StreamingAssets/twin/roads.json` keeps every current field (`nodes`, `edges[{a,b,c,len,g,y}]`, `classes`, `external`) so all current readers still work; old class `c` is derived (expressway → highway, BAKAD → ring, arterial_* and district_* → main, everything else → street). New optional fields per edge: `t` (norms class), `k` (0 two-way, 1 one carriageway of a divided road, 2 ramp), `h` (surface heights, one per vertex of `g`), `st` (flat `[from_m,to_m,code,…]`, code 0 ground 1 embankment 2 cut 3 bridge 4 overpass 5 tunnel), `p` (index into new top-level `profiles`), `ic` (interchange index), `ps` ([{y:[4], p}]: the profile `p` from the years `y` on, a reconstruction such as a ramp widened, network segments[].stages). `Resources/Landmarks/film_roads.json` is written from the same edges (stroke i = edge i, `drop` empty for new data); w45 decides whether Unity still needs it and documents it here. Readers must behave exactly as today when the new fields are absent.
- Buildings (w45 writes): `CityData/buildings.csv`, `CityData/layer_buildings.bytes` (AQL1; kept meshes copied by bid, new buildings extruded from footprints with flat roofs, existing chunking rules), `Resources/Landmarks/bid_bounds.bytes`, `hide_extra.bytes`, `map_order.json` (the hide lists shrink: new data has nothing to hide), every per-bid array (`construction.json per_building`, `risk.json`, anything else keyed by bid). Bid rule in mode «district + current data»: kept buildings keep their bid; new buildings take free numbers (numbers of removed buildings, then numbers no kept building uses), preferring the district range from `city.json#bids`; all < 131 072 (see §8, w49), unique; the mapping goes to the manifest. ## 8. Settled at level 1 (from the workers' reports; these override §3–§6 where they differ)

Export and Unity (w45):
- `roads.json` profiles: `[{id "district:pid", t, lanes[f,b], lane_w, median_w, sidewalk_w[l,r], verge_w[l,r], bike_w[l,r], parking_w[l,r], red_line_w}]`. Interchanges: `[{id, template, x, z}]`. `version` gets ` · merge <run>`. New edges have `g` rounded to 1 decimal; `st` is left out when the whole edge is on the ground; `ic` is left out when there is no interchange.
- `film_roads.json` v2: top level `v:2` and `profiles`; strokes `{c,k,a,b,y,g,e,p,ic,t,h,st}`, where `e` is the roads edge. Old strokes get `e/p/ic = −1` and are clipped at the area. `zones [x,z,r,y]` (at most 32); `drop` is remapped.
- The buildings layer is written in parts: `layer_buildings.bytes`, `_1`, `_2` and so on, each AQL1 and at most 24 MB. A chunk is never split unless it is bigger than a part, and a bid is never in two parts. The manifest lists them under `layer_parts`. AlatauCityBuilder reads all parts and refuses a bid that appears twice (a stale part). The DataStamp hashes every part.
- Solar: on every merge all kind-solar rows of the whole city leave the layer mesh and become fields in `solar.json`. The CSV rows stay (kind solar, no mesh), so bids and per-bid arrays don't change. A district's `buildings.json` with a `"solar"` key (even an empty list) replaces the twin panels inside its area. `--keep-solar` turns the move off.
- Size guard: merge refuses to write any file over 24,000,000 bytes, and the run is then incomplete with no manifest.
- Merge defaults: snap 2 m, stitch up to 80 m, otherwise log a gap. Removed rows become placeholders: kind `removed`, year 2099. Bid order: removed numbers in the district range, then free numbers in the range, then other removed numbers, then append.
- Unity log lines: `[Alatau] film roads v2: …`, `[Alatau] film traffic: N ramp lanes …`, `[Alatau] counters cars_off=… people_off=… ramp_cars=… ramp_in=…` (every 10 s and at stop).
- Scripts that read only a single-file layer and must learn parts before a layer is split: `tools/relocate_industry.py`, `tools/spread_social.py`, `tools/map/geo/twin.py`.

Roads, LRT and validator (w43):
- Spec features:
  - `omit_quadrants` is honoured.
  - `hand_ramps` are tagged to their interchange and may share their end node with a street.
  - `ramps_hint` is only logged.
  - `edge_joints.street: null` gives a log line. Joints are matched one to one, nearest first.

- A house is 25 m² or more; anything smaller is a shed, and the count of sheds is logged.
- The generated local grid is off for v1 specs (`--grid` turns it on).
- network.json:
  - mid-block crossings are 2-arm `crossing` nodes;
  - joint ids are `<ref>@<node>` when no edge joint matches.
- lrt.json:

Land, buildings and masks (w44):
- `OUT/<d>/driveways.json` is written at the end of gen_buildings, in the §4 network format.
  - Each street connection is a node with `attach {segment, x, z}`.
  - Turnaround pads appear as `node.turnaround` and in `pads[]` (15 × 15 m at every dead end).
  - Per block the drives form one tree, rooted only on streets already open in the building's years, and they keep off the LRT ground corridor.
  - Buildings over 28 m get a fire lane 8–10 m from the wall; a ring is required where `fire_access.ring_required` says so.

- Blocks, lots and greens may carry `holes` (inner rings; shapely-valid).

- The rule module for years is `validate/rules/years.py`, not time.py, which shadowed the stdlib.
- Defaults:
  - driveway_secondary is never used, because its 3.5 m carriageway is below the 6 m fire width;
  - a drive may drop its sidewalks in tight gaps;
  - high-rise zones keep 22 m fire gaps;
  - office and retail parking stays 0 while those norms are not_verified.

Level 1 tool fixes (w43, after the trial):
- Rule 25 measures LRT slope over a chord of `lrt_slope_base_m` (MODEL constant, 20 m) and between neighbouring vertices. Each height difference is reduced by `height_round_tol_m`, so rounding never gives an error.
- Spec streets that continue each other end to end (ends within 1.5 m, directions within 30°) count as one road for end snapping. A split divided street gives one junction.
- Automatic rings: at most one per junction, centred on the spec node within 30 m and named `ring_<node id>`. The log says the spec type was replaced under rule 6.
- partial_cloverleaf:
  - a `quadrants` entry is a quadrant that gets ramps;
  - a direction without a loop gets diamond ramps, joined by one connector across the median of a divided minor road;
  - invalid variants are refused with a message naming the variant (unknown quadrant, outer ramp without its loop, no loop at all, a terminal 1–29 m before the end of the minor road).
- `run.py <path>.json` passes `--spec` to the land tools.

Level 1 land fixes (w44, after the trial):
- Rule-12 distances are measured from the wall to the carriageway polygon, with flat caps, in both the generator and the validator.
- Dead ends:
  - every dead end has a 15 × 15 pad (square, or a T or L shape) within 40 m of its end; where none fits, it becomes a loop through the yard;
  - a dead-end piece is at most 150 m long;
  - ring pieces are linked at both ends, and no drive segment starts and ends at the same node.
- place_services counts spec and registry capacities and keep-quarter residents, and spreads zone densities over net block area.
- Social plots are checked with `land_models.social_place` and grown up to ×2.2; when the building still doesn't fit, the site is skipped.
- Lots smaller than the zone's smallest lot are merged, terraced or turned green. Reserve lots are always labelled.
- The houses split places one detached house per plot.
- The 25 m² minimum for a house also applies to twin rows.
- An overlap between two existing objects is a warning.
- Greens are reached at their edge, with entrances every 40 m. A provider on the house's own lot is measured straight across.
- A logistics building is one class-A shed at most: ≤ 50,000 m², ≤ 300 m long, 120–200 m deep. Truck yards are 35–40 m and there are fire gaps between sheds. Rule 18 checks the size.

Level 1 drives and traffic (w45):
- Drives: each driveways segment becomes a roads edge, placed after all street edges. Its t is its class, c is street, h comes from the terrain, p is `<d>:<pid>` (or `<d>:dw.<pid>` on a clash), and `sv` lists the bids it serves.
- An attach node splits its street edge. Within 1 m of an end or of another attach, that node is reused. The pieces keep the street's fields; h is interpolated and st is re-based.
- film_roads: a split street stays one stroke, with e = its first piece and es = all its pieces in order. Drive strokes have a/b = −1 at the attach end. New key `pads: [{n, p, y}]`.
- The manifest carries `drives` (counts and attach_nodes).
- Traffic: trips run building to building, through the street each building fronts or through its `sv` drives. Drives and carless edges (pedestrian, bike, profiles with no lanes) are never routed. One-way edges follow point order. Parallel edges between the same nodes share flow by capacity. 3 passes with seeded cost noise × U(0.85, 1.18).
